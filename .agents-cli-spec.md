# TaaS POC Scope

## Goal

Build a simple Google Cloud Terraform-as-a-Service proof of concept with Gemini
ADK. A user describes a resource request in chat; the agent collects required
values, uses an approved Terraform starter, shows a plan, and applies only after
the user approves it.

## Phase 1

- Use the ADK web interface.
- Support BigQuery dataset as the initial resource with generic tools ready for multi-resource expansion.
- Keep user guidance in `taas_agent/skills/terraform-provisioning/SKILL.md`.
- Keep deterministic Python operations in `taas_agent/tools/tools.py`.
- Keep Terraform starter files separate under `terraform_starters/`.
- Generate reviewable Terraform artifacts for the user to commit manually.
- Store authoritative Terraform state in an existing, versioned GCS bucket with isolated resource state keys.
- Require an explicit ADK confirmation before applying any saved plan.
- Support resource deactivation (commenting out .tf files and applying destroy) and recreation (uncommenting and applying create).
- Verify resources after apply and report ready or deleted accurately.
- Do not add authentication infrastructure, email, GitHub integration, AWS,
  EnterpriseGPT changes, or unrequested cloud resources in this phase.

## Later phases

1. Integrate the stable TaaS backend with EnterpriseGPT without changing the
   existing frontend during Phase 1.
2. Add more Google Cloud data engineering and ML resource starters (GCS, Dataproc, Vertex AI).
3. Add AWS data engineering resources (S3, Glue, EMR).

## Provisioning boundary

The application must never create the GCS state bucket or change IAM
automatically. The bucket must already exist and have object versioning enabled
before Terraform planning. The model cannot provide arbitrary Terraform source
or shell commands. Any plan with changes other than the requested target resource
action must be blocked.
